# ADR-0015: انتشار رویداد پرداخت موفق برای Ordering و Loyalty

## وضعیت

Accepted

## زمینه

پس از ثبت پرداخت موفق، Ordering باید وضعیت سفارش را تغییر دهد و Loyalty باید امتیاز مشتری را افزایش دهد.

اگر Payments هر دو سرویس را به‌صورت هم‌زمان فراخوانی کند، موفقیت پرداخت به دسترس‌پذیری آن‌ها وابسته می‌شود و Temporal Coupling و شکست آبشاری ایجاد می‌شود.

## تصمیم

Payments پس از ثبت موفق پرداخت، Integration Event نسخه‌دار `PaymentSucceededV1` را منتشر می‌کند.

Ordering و Loyalty مصرف‌کنندگان مستقل این رویداد هستند. هر مصرف‌کننده داده و تراکنش محلی خود را مدیریت می‌کند.

قرارداد رویداد شامل شناسه رویداد، زمان رخداد، شناسه پرداخت، شناسه سفارش، شناسه مشتری و مبلغ پرداخت‌شده است.

## پیامدها

### مثبت

- پرداخت به دسترس‌پذیری لحظه‌ای Loyalty وابسته نیست.
- مصرف‌کنندگان جدید بدون تغییر مستقیم Payments اضافه می‌شوند.
- Workflow به‌صورت واقعی غیرهم‌زمان و قابل مشاهده می‌شود.

### منفی

- وضعیت سرویس‌ها برای مدتی ناسازگار است.
- ترتیب، تکرار و گم‌شدن پیام باید مدیریت شود.
- قرارداد رویداد نیازمند Governance و نسخه‌بندی است.

## گزینه‌های بررسی‌شده

### فراخوانی HTTP مستقیم پس از پرداخت

رد شد؛ زیرا نتیجه پرداخت را به دسترس‌پذیری مصرف‌کنندگان وابسته می‌کند.

### دسترسی مستقیم به دیتابیس Ordering و Loyalty

رد شد؛ زیرا مالکیت داده و مرز سرویس را نقض می‌کند.
