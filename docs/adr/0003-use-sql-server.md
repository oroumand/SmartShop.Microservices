# ADR-0003: استفاده از SQL Server

## وضعیت

Accepted

## زمینه

SmartShop به persistence برای ذخیره محصولات، سفارش‌ها و پرداخت‌ها نیاز دارد.

از آنجا که پروژه با ASP.NET Core و EF Core توسعه داده می‌شود، SQL Server یک انتخاب طبیعی و مناسب برای کارگاه است.

نیازهای persistence عبارت‌اند از:

- پشتیبانی از relational data
- سازگاری خوب با EF Core
- امکان تعریف schemaهای جدا برای ماژول‌ها
- اجرای ساده با Docker Compose
- آشنا بودن برای بسیاری از توسعه‌دهندگان .NET
- مناسب بودن برای سناریوهای transactional مانند سفارش و پرداخت

## تصمیم

برای persistence اصلی SmartShop از SQL Server استفاده می‌کنیم.

همه ماژول‌ها از یک database فیزیکی استفاده می‌کنند، اما هر ماژول schema اختصاصی خودش را دارد.

schemaهای اولیه:

- catalog
- ordering
- payment
- ai

## پیامدها

### پیامدهای مثبت

- SQL Server با EF Core بسیار خوب کار می‌کند.
- مدل relational برای سفارش، آیتم سفارش، پرداخت و محصول مناسب است.
- اجرای local با Docker Compose امکان‌پذیر است.
- استفاده از schema جدا به حفظ ownership ماژول‌ها کمک می‌کند.
- برای مخاطبان .NET معمولاً آشنا است.
- مسیر مهاجرت به database جدا برای هر سرویس در آینده قابل توضیح است.

### پیامدهای منفی

- استفاده از یک database فیزیکی باعث می‌شود isolation کامل داده‌ها نداشته باشیم.
- اگر مراقب نباشیم، امکان join مستقیم بین schemaهای مختلف وجود دارد.
- برای حفظ مرز ماژول‌ها باید قوانین معماری و code review داشته باشیم.
- scaling دیتابیس برای ماژول‌ها مستقل نیست.

## گزینه‌های بررسی‌شده

### PostgreSQL

مزیت‌ها:

- open-source
- امکانات قوی
- مناسب برای سیستم‌های مدرن

دلیل انتخاب نشدن:

- تمرکز استک کارگاه روی .NET و SQL Server است.
- SQL Server برای مخاطبان این کارگاه آشناتر است.

### SQLite

مزیت‌ها:

- بسیار ساده
- بدون نیاز به سرویس جدا
- مناسب برای دموهای کوچک

دلیل انتخاب نشدن:

- برای نمایش schema-per-module و سناریوهای واقعی‌تر سازمانی مناسب نیست.
- برای کارگاه معماری enterprise-like انتخاب ضعیف‌تری است.

### Database جدا برای هر ماژول

مزیت‌ها:

- isolation بهتر
- نزدیک‌تر به Microservices

دلیل انتخاب نشدن:

- پیچیدگی بیش از حد برای کارگاه 4 ساعته
- افزایش سربار setup
- نیاز به مدیریت connection string و migrationهای جداگانه بیشتر
