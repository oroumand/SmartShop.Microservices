# اسکریپت‌های k6 برای تست پرفورمنس

این پوشه شامل اسکریپت‌های آماده برای مرحله‌های بعدی کارگاه است.

این اسکریپت‌ها در build معمولی پروژه اجرا نمی‌شوند و برای اجرای `dotnet build` به نصب k6 نیاز نیست. در وضعیت فعلی فقط فایل‌ها آماده شده‌اند و لازم نیست روی این ماشین اجرا شوند.

## اجرای نمونه در آینده

بعد از اینکه API اجرا شد و k6 روی ماشین نصب بود، می‌توان اسکریپت‌ها را به این شکل اجرا کرد:

```bash
k6 run perf/k6/smoke.js
k6 run -e BASE_URL=http://localhost:5217 perf/k6/order-payment-flow.js
```

اگر `BASE_URL` مشخص نشود، مقدار پیش‌فرض اسکریپت‌ها این است:

```text
http://localhost:5217
```

## فایل‌ها

### smoke.js

یک تست بسیار سبک برای بررسی در دسترس بودن API است.

این اسکریپت endpointهای زیر را صدا می‌زند:

- `GET /health`
- `GET /api/catalog/products`
- `GET /api/orders`
- `GET /api/payments`

### catalog-load.js

یک تست read-heavy ساده برای Catalog است.

این اسکریپت لیست محصولات و دو جستجوی معمولی را صدا می‌زند:

- `GET /api/catalog/products`
- `GET /api/catalog/products/search?query=laptop`
- `GET /api/catalog/products/search?query=phone`

### order-payment-flow.js

یک جریان ساده کسب‌وکاری را تست می‌کند:

1. دریافت محصولات
2. انتخاب اولین محصول
3. ثبت سفارش
4. ثبت پرداخت
5. دریافت دوباره سفارش

اگر Catalog خالی باشد، اسکریپت خطای JavaScript نمی‌دهد و فقط check مربوط به وجود محصول fail می‌شود.

### ai-search-smoke.js

این اسکریپت برای مرحله‌های بعدی جستجوی هوشمند آماده شده است.

برای اجرای موفق آن، Qdrant و تنظیمات OpenAI باید آماده باشند. تا زمانی که این وابستگی‌ها تنظیم نشده‌اند، انتظار می‌رود این اسکریپت fail شود.

## نکته برای اجرای محلی

تست‌های سنگین را بدون تنظیم تعداد VU و duration روی لپ‌تاپ اجرا نکنید. مقدارهای فعلی عمداً کم و آموزشی هستند تا بعداً برای اجرای local قابل کنترل باشند.
